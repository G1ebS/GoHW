# Starter СР-1

## Задание

Реализуйте анализатор продаж:

```go
func AnalyzeSales(sales []Sale) Report
```

Для каждой продажи известны товар, категория, количество, цена за единицу в
копейках и признак отмены. Функция должна:

- рассчитать общую выручку в копейках;
- посчитать число проданных единиц;
- собрать выручку по категориям;
- определить самый продаваемый товар по количеству единиц;
- посчитать некорректные записи;
- не изменять исходный срез.

## Правила

- Запись некорректна, если товар или категория пусты, количество не положительно
  либо цена не положительна.
- Некорректная запись не участвует в остальных расчётах и увеличивает
  `InvalidSales`.
- Отменённая продажа пропускается раньше валидации: она не входит в отчёт и не
  считается некорректной.
- При равном количестве проданных единиц лидером становится лексикографически
  меньшее название товара.
- Для пустого входа возвращается отчёт с нулевыми значениями и созданной пустой
  `RevenueByCategory`.
- Используйте только структуры, срезы, `map`, условия, циклы и функции.
  Интерфейсы, горутины и сторонние библиотеки не нужны.

Перед сдачей добавьте в этот README краткое описание алгоритма и его сложности.

## Как работает решение

В `AnalyzeSales` сначала создаётся отчёт с пустой `RevenueByCategory` и отдельная
`map` для количества проданных единиц каждого товара. Затем продажи обрабатываются
одним проходом:

1. Отменённые продажи сразу пропускаются, даже если у них некорректные поля.
2. Некорректные записи увеличивают `InvalidSales` и не участвуют в расчётах.
3. Для остальных записей выручка считается как количество, умноженное на цену
   в копейках. Она добавляется в общую выручку и выручку категории, а количество —
   в `UnitsSold` и счётчик соответствующего товара.

После этого отдельным проходом по товарам выбирается лидер по количеству проданных
единиц. Если количество одинаковое, через `min` выбирается лексикографически меньшее
название, поэтому результат не зависит от порядка обхода `map`.

Исходный срез не изменяется: функция только читает записи, а результаты собирает
в новых структурах и картах. Для пустого или nil-среза возвращаются нулевые значения
и созданная пустая `RevenueByCategory`.

## Сложность

Пусть `n` — число входных записей, `p` — число разных товаров среди корректных
неотменённых продаж, `c` — число их категорий.

- Тогда асимптотическая сложность `O(n + p)`, то есть `O(n)`, потому что `p <= n`.
  Один проход нужен для продаж, второй — для выбора лидера среди товаров.
